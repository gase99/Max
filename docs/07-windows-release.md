**نسخه:** ۰٫۱٫۰ · **آخرین به‌روزرسانی:** ۲۰۲۶/۱۰/۲۴
**آخرین بیلد تأییدشده:** run `40131272368` (کامیت `2db4bee`) — همهٔ مرحله‌ها موفق،
۱۱۶/۱۱۶ بررسی فاز ۱ و ۱۲/۱۲ بررسی فاز ۲

## ۱. خلاصه

نصب‌کنندهٔ ویندوز با **GitHub Actions روی ماشین ویندوز واقعی** (`windows-latest`) ساخته و
**در همان محیط اجرا و تأیید** می‌شود. این محیط لینوکسی است و بدون `wine` نمی‌تواند نصب‌کننده
ویندوز بسازد؛ بنابراین تنها مسیر معتبر، همان workflow است.

| مورد | وضعیت |
|---|---|
| تست‌ها پیش از بسته‌بندی | ✅ ۲۱۶ تست (۱۵۸ موتور + ۵۸ رابط) |
| ساخت نصب‌کننده NSIS و Portable | ✅ |
| تأیید وجود و اندازهٔ فایل‌ها | ✅ |
| اجرای برنامه در Electron ویندوز | ✅ ۱۱۶ بررسی فاز ۱ + ۱۲ بررسی فاز ۲ |
| اجرای برنامهٔ بسته‌بندی‌شده | ✅ ماندگار برای ۱۵ ثانیه |
| نصب و اجرای نسخهٔ نصب‌شده | ✅ |
| امضای دیجیتال کد | ❌ ندارد (گواهی موجود نیست) |
| تست روی دستگاه فیزیکی ویندوز | ❌ انجام نشده — روی ماشین مجازی GitHub |

## ۲. دریافت فایل نصب

1. به مخزن بروید: `https://github.com/gase99/Max/actions`
2. روی آخرین اجرای موفق **Windows release** کلیک کنید.
3. در پایین صفحه بخش **Artifacts** → دانلود کنید:
   `cabinet-analysis-pro-windows-<commit>`

داخل فایل ZIP:

| فایل | کاربرد |
|---|---|
| `Cabinet-Analysis-Pro-Setup-0.1.0.exe` | نصب‌کنندهٔ معمول (NSIS، x64) |
| `Cabinet-Analysis-Pro-Portable-0.1.0.exe` | نسخهٔ بدون نصب |
| `latest.yml` + `*.blockmap` | فرادادهٔ به‌روزرسانی (در صورت فعال بودن publish تولید می‌شود) |

> فایل نصب **امضای دیجیتال ندارد**. ویندوز ممکن است پیام SmartScreen نشان دهد؛
> با «More info → Run anyway» ادامه دهید. متن‌باز بودن مخزن و قابل بازبینی بودن
> بیلد، جای امضای تجاری را نمی‌گیرد اما ریسک را شفاف می‌کند.

### ساخت دستی بیلد جدید

`Actions → Windows release → Run workflow`

با فعال‌کردن گزینهٔ `publish_release`، نسخهٔ **Draft Release** در GitHub منتشر می‌شود
(پیش‌نویس، نه منتشرشده — انتشار نهایی با تأیید شما انجام می‌شود).

## ۳. نصب

### روش معمول

1. `Cabinet-Analysis-Pro-Setup-0.1.0.exe` را اجرا کنید.
2. مسیر نصب را انتخاب کنید (پیش‌فرض: `%LOCALAPPDATA%\Programs`).
3. میان‌بر روی دسکتاپ و منوی Start ساخته می‌شود.
4. برنامه را اجرا کنید.

نصب **برای کاربر جاری** است و به دسترسی Administrator نیاز ندارد.

### نسخهٔ Portable

فایل `Cabinet-Analysis-Pro-Portable-0.1.0.exe` را روی فلش یا پوشهٔ دلخواه اجرا کنید.
هیچ چیزی نصب نمی‌شود. داده‌ها همچنان در پروفایل کاربر ذخیره می‌شوند (نه کنار فایل اجرایی).

### حذف

`Settings → Apps → Cabinet Analysis Pro → Uninstall`
یا اجرای `Uninstall Cabinet Analysis Pro.exe` در پوشهٔ نصب.

## ۴. کارکرد آفلاین

پس از نصب، برنامه **به هیچ اینترنتی نیاز ندارد**:

- محاسبات، ذخیره‌سازی، خروجی CSV و چاپ همه محلی‌اند.
- پوستهٔ دسکتاپ هیچ درخواست شبکه‌ای انجام نمی‌دهد؛ این مورد در تست زمان اجرا
  به‌صورت خودکار بررسی می‌شود (`no http(s) request`).
- مسیر بستهٔ وب (خارج از دسکتاپ) از Service Worker استفاده می‌کند تا پس از
  نخستین بارگذاری، آفلاین هم باز شود. این قابلیت روی `file://` در دسکتاپ
  غیرفعال است (پشتیبانی نمی‌شود) و لازم هم نیست.

## ۵. دقیقاً چه چیزی تأیید شده است؟

workflow پنج مرحلهٔ مستقل دارد و هر مرحله با شکست، بیلد را متوقف می‌کند.

### ۵.۱ تست‌ها (Linux)

| آزمون | نتیجه |
|---|---|
| ۱۵۸ تست موتور محاسبه (شامل هم‌ارزی سلول‌به‌سلول با اکسل) | ✅ |
| ۵۸ تست رابط کاربری (jsdom، شامل اجرای اسکریپت‌های smoke) | ✅ |
| مجموع | ✅ ۲۱۶ / ۲۱۶ |
| syntax-check همهٔ نقطه‌های ورود دسکتاپ (`main`, `preload`, `build-renderer`, `verify-package`, `smoke-test`) | ✅ |
| typecheck و ساخت declaration موتور | ✅ |
| ساخت نسخهٔ production وب | ✅ |

در ماشین ویندوز، `npm run test:all` **دوباره** اجرا می‌شود تا اگر رفتار platform-specific
متفاوت بود، پیش از بسته‌بندی مشخص شود.

### ۵.۲ تأیید خروجی‌ها (`verify-package.cjs`)

- هر دو فایل `.exe` وجود دارند و بزرگ‌تر از ۴۰ مگابایت‌اند (اگر بسته‌بندی ناقص باشد، رد می‌شود).
- `app.asar` شامل `app/index.html`، `main.cjs`، `preload.cjs` و دست‌کم یک asset جاوااسکریپت است.
- `index.html` داخل asar **مسیرهای نسبی** دارد (شرط لازم برای `file://`).
- SHA-256 هر دو فایل چاپ و در گزارش ثبت می‌شود.

این اسکریپت با یک بستهٔ سالم و یک بستهٔ معیوب آزمایش شده است تا مطمئن شویم واقعاً
رد می‌کند و «همیشه سبز» نیست.

### ۵.۳ تست زمان اجرا (`smoke-test.cjs`) — روی ویندوز

برنامهٔ واقعی الکترون با بیلد واقعی، در دو **فرایند مستقل** و روی یک پروفایل مشترک اجرا
می‌شود. نتیجهٔ آخرین اجرای تأییدشده: **۱۱۶/۱۱۶** در فاز ۱ و **۱۲/۱۲** در فاز ۲.

| حوزه | نمونهٔ بررسی‌ها |
|---|---|
| ۱. نصب و اجرا | نصب‌کننده در حالت بی‌صدا نصب و اجرا می‌شود؛ `app.asar` هم اجرا و زنده‌ماندنش تأیید می‌شود |
| ۲. ساخت پروژه و ذخیره | نام/مشتریِ تایپ‌شده، ساخت پروژه با دکمهٔ «جدید»، افزودن کابینت زمینی و هوایی، ذخیرهٔ عرض ۱۰۰ سانتی‌متر در فایل پروژه |
| ۳. بستن و باز کردن | فاز ۲ در **فرایند جدید** همان پروفایل را باز می‌کند: پروژه، نام، ابعاد و نتایج (۹۶۸ میلی‌متر) سر جایشان هستند |
| ۴. پشتیبان و بازیابی | فایل پشتیبان واقعی روی دیسک نوشته و از دیسک خوانده می‌شود؛ فایل خراب و JSON ساختاراً غلط رد می‌شوند و داده تغییر نمی‌کند |
| ۵. خروجی CSV و DXF | بایت‌های واقعی فایل بررسی می‌شوند: BOM، ‏CRLF، تعداد ستون ثابت، ردیف ۹۶۸/۹۸۴؛ DXF: ‏`AC1009`، `$INSUNITS=4`، لایه‌ها، ‏`EOF` |
| ۶. چاپ نقشهٔ دوبعدی | بستهٔ HTML روی دیسک و **مسیر واقعی چاپ Chromium** (`printToPDF`): فایل `%PDF`، ‏MediaBox ‏A4 (۵۹۵×۸۴۲)، یک صفحه به‌ازای هر برگه. تعداد برگه‌ها ≥ تعداد واحدها و شمارهٔ برگه‌ها ۱..N بدون جا افتادن |
| ۷. آفلاین و راه‌اندازی دوباره | هیچ درخواست `http(s)` ثبت نمی‌شود؛ بازگشایی مجدد در فاز ۲ همان داده را نشان می‌دهد |
| ۸. فارسی/راست‌به‌چپ/فونت/انگلیسی | جهت و زبان پیش‌فرض، پشتهٔ فونت (Vazirmatn → Tahoma/Segoe UI)، عرض غیرصفر متن فارسی، جابه‌جایی به انگلیسی/چپ‌به‌راست و برگشت |
| ۹. ورودی نامعتبر و خطای ذخیره‌سازی | عرض ۰، عرض ۱۰۰۰ متر، شکست واقعی `localStorage.setItem` (QuotaExceeded) — برنامه زنده می‌ماند و پیام می‌دهد |

**آنچه این تست نیست:** یک دستگاه فیزیکی ویندوز، چاپگر واقعی، آنتی‌ویروس یا زنجیرهٔ
امضای کد. این موارد در `docs/12-workshop-guide.md` §۵ صریحاً «تأییدنشده» فهرست شده‌اند.

نتیجه در artifact `smoke-report-<sha>` (`smoke-report.json` و `smoke-report-phase2.json`)
ذخیره می‌شود.

### ۵.۴ بستهٔ بسته‌بندی‌شده

`release/win-unpacked` — همان درختی که در نصب‌کننده بسته می‌شود — اجرا و ۱۵ ثانیه
زنده‌ماندنش بررسی می‌شود.

### ۵.۵ نصب واقعی و SHA-256

نصب‌کننده به‌صورت `/S` نصب می‌شود، فایل اجرایی نصب‌شده پیدا و اجرا می‌شود و
۱۵ ثانیه زنده‌ماندن آن تأیید می‌شود.

SHA-256 هر دو فایل در هر اجرا محاسبه و به‌صورت annotation در همان اجرا ثبت می‌شود.
مقادیر آخرین اجرای تأییدشده (run `40131272368`، کامیت `2db4bee`):

| فایل | SHA-256 |
|---|---|
| `Cabinet-Analysis-Pro-Setup-0.1.0.exe` | `d6bc4a891fac5130da33bf8fe514670bd6494e46ff6134d3a11ab3229a47e2d9` |
| `Cabinet-Analysis-Pro-Portable-0.1.0.exe` | `d2517276306015ab6f204db291bbf57559c729124de520093a74424bc75a723f` |

> ⚠️ SHA-256 با هر کامیت تغییر می‌کند. برای نسخهٔ خودتان، عدد را از annotation همان
> اجرا یا از خروجی مرحلهٔ «Installer SHA-256» بخوانید. `app.asar` اما در دو بیلد مستقل
> بایت‌به‌بایت یکسان بود (`2def0273…`)، یعنی ساخت تکرارپذیر است.

## ۶. آنچه هنوز تأیید نشده است

صادقانه:

1. **دستگاه فیزیکی ویندوز ۱۰/۱۱:** همهٔ اجراها روی ماشین مجازی GitHub بودند.
   تست نهایی روی یک سیستم واقعی کارگاه هنوز انجام نشده است.
2. **امضای کد:** نصب‌کننده امضا نشده؛ SmartScreen هشدار می‌دهد.
3. **پایداری بوت‌استرپ NSIS:** در یکی از اجراها نصب‌کننده با کد
   `0xC0000005` (access violation) کرش کرد، در حالی که بیلد و اجرای برنامه سالم بود.
   این خرابی به‌صورت متناوب و مربوط به محیط ماشین مجازی است، نه به برنامه.
   به همین دلیل مرحلهٔ نصب ۳ بار تلاش می‌کند.
4. **نسخه‌های ۳۲ بیتی:** فقط `x64` ساخته می‌شود.
5. **به‌روزرسانی خودکار:** `latest.yml` تولید می‌شود اما سرور به‌روزرسانی پیکربندی نشده.
